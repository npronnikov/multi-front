# Архитектура: back

**Repo alias:** `back`

## Назначение репозитория

`multi-front` — это фронтенд-клиент для приложения «To-Do List», построенный на Next.js 16 / React 19 / TypeScript / Tailwind CSS v4. Представляет собой клиентский SPA, обеспечивающий пользовательский интерфейс для управления задачами через REST API бэкенд-сервиса (`multi-back`).

## Наблюдения по архитектуре

1. **Полностью клиентский рендеринг без серверных компонентов.** Единственная страница `app/page.tsx` помечена `"use client"`. Весь рендеринг, управление состоянием и загрузка данных происходят в браузере. Серверные компоненты Next.js и API-роуты не используются, что упрощает архитектуру, но лишает преимуществ SSR/SSG.

2. **Оптимистичные обновления для toggle и delete.** Методы `toggleTodo` и `deleteTodo` немедленно обновляют UI, а затем отправляют запрос к API. При ошибке выполняется откат к предыдущему состоянию. Это паттерн, улучшающий отзывчивость интерфейса, но требующий аккуратной обработки ошибок для поддержания консистентности.

3. **Tailwind CSS v4 с новой PostCSS-интеграцией.** Проект использует `@import "tailwindcss"` вместо устаревших `@tailwind`-директив и плагин `@tailwindcss/postcss` вместо отдельного `tailwind.config.js`. Конфигурация тем реализована через `@theme inline` и CSS custom properties, что соответствует актуальным конвенциям Tailwind v4.

4. **Отсутствие выделенного state-менеджмента и компонентной декомпозиции.** Всё состояние управляется через `useState` / `useEffect` в одном компоненте. Нет разделения на переиспользуемые UI-компоненты, хуки для работы с API или контекст провайдеры. Для масштабирования потребуется рефакторинг с выделением ответственности.

5. **Нестандартная версия Next.js с предупреждением для AI-агентов.** Файл `AGENTS.md` явно указывает, что используемая версия Next.js содержит breaking changes по сравнению с общепринятыми конвенциями, и требует консультации с документацией в `node_modules/next/dist/docs/` перед внесением изменений в код. Это критическое предупреждение для автоматизированной разработки.
