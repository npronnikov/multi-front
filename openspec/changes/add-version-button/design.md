# Design: Add Version Button

## Overview
Добавление кнопки "Version" в header приложения с отображением modal-окна при клике. Реализация выполняется на Frontend (Next.js/React) без изменений в backend API для начальной версии.

## Decisions

### Decision: Использование React Modal для отображения версии
**Выбор:** Создание собственного modal-компонента с использованием Tailwind CSS
**Обоснование:**
- Минимальные зависимости
- Полный контроль над стилем и поведением
- Легкая интеграция с существующим Next.js приложением
**Альтернативы:**
- Использование готовой библиотеки (react-modal, Radix UI) — избыточно для одного modal

### Decision: Хранение версии приложения
**Выбор:**
- Frontend версия: из package.json
- Backend версия: хардкод в константе (начальная реализация)
**Обоснование:**
- Простота реализации
- package.json является стандартным источником версии для npm-пакетов
- Backend версия может быть позже получена через API endpoint
**Альтернативы:**
- API endpoint /api/version — требует изменений в backend
- Переменные окружения — добавляет сложность конфигурации

### Decision: Размещение кнопки в header
**Выбор:** Правая часть header приложения
**Обоснование:**
- Стандартная практика для информационных элементов
- Не мешает основной функциональности (форма добавления todo)
- Консистентно с современными UI паттернами
**Альтернативы:**
- Footer — менее заметно
- Рядом с формой добавления — визуальный шум

### Decision: Стиль кнопки и modal
**Выбор:** Использование Tailwind CSS классов, консистентных с существующим UI
**Обоснование:**
- Проект уже использует Tailwind CSS
- Гарантия консистентности дизайна
- Поддержка темной/светлой темы через prefers-color-scheme
**Альтернативы:**
- Custom CSS — дублирование стилей

## Data Model
Изменений в модели данных нет. Версия приложения — статическая информация, не требующая persist.

## Implementation Notes

### Frontend (Next.js)
**Файлы для изменения:**
- `app/page.tsx` — добавление кнопки в header и state для modal
- Создание компонента `VersionModal` (можно в отдельном файле или inline)

**Технические детали:**
1. **State management:**
   - `showVersionModal: boolean` — состояние видимости modal
   - Использование `useState` hook

2. **Версия приложения:**
   - Frontend версия: читается из `package.json` или константы
   - Backend версия: константа (начальная реализация)

3. **Modal Component:**
   - Conditional rendering: `{showVersionModal && <VersionModal onClose={...} />}`
   - Backdrop: затемненный фон с закрытием при клике вне modal
   - Accessibility: закрытие по Escape key

4. **Styling:**
   - Кнопка: `px-4 py-2 rounded-lg bg-blue-500 text-white hover:bg-blue-600`
   - Modal: `fixed inset-0 flex items-center justify-center z-50`
   - Modal content: `bg-white dark:bg-gray-800 rounded-lg p-6`

### Backend (Spring Boot)
**Изменения не требуются** для начальной реализации. Backend версия может быть захардкожена или взята из pom.xml при необходимости.

## Risks

### Технические риски
- **Интеграция с существующим UI:** Риск несоответствия стилей
  - **Митигация:** Использование существующих Tailwind классов из проекта
- **State management:** Ошибки с conditional rendering modal
  - **Митигация:** Простая реализация с одним boolean state

### UX риски
- **Неочевидность функциональности:** Пользователь может не понять назначение кнопки
  - **Митигация:** Понятный label "Version", консистентный стиль с другими action buttons

### Будущая совместимость
- **Backend версия:** В будущем может потребоваться dynamic получение версии через API
  - **План:** Оставить возможность для добавления API endpoint без изменения UI
